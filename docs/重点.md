#### 智能体的核心组件

- **大语言模型（LLM）**：Agent 的“大脑”，负责理解和生成语言、进行推理和决策。
- **记忆模块（Memory）**：存储历史交互信息，解决 LLM 的无状态性问题。
- **规划模块（Planning）**：将复杂目标分解为可执行的子任务。
- **工具使用（Tool Use）**：让 Agent 能够调用外部 API、代码执行器、搜索引擎等扩展能力。

#### 大语言模型的局限

| 局限               | 含义                                          | 对 Agent 开发的影响                          |
| ------------------ | --------------------------------------------- | -------------------------------------------- |
| **上下文窗口限制** | 一次能处理的 token 数有上限，超出会截断或遗忘 | 需要实现记忆压缩、对话总结或 RAG             |
| **无状态性**       | 每次调用都是独立的，不记得历史对话            | 必须自行实现记忆管理（会话缓存、向量数据库） |
| **事实幻觉**       | 可能生成与事实不符的内容                      | 需要使用 RAG 或外部知识库验证                |
| **推理稳定性**     | 复杂推理可能出错或不一致                      | 需要设计规划模块和验证机制                   |
| **工具调用准确性** | 生成工具调用参数可能出错                      | 需要校验和重试机制                           |


#### Transformer 架构

**为什么需要 Transformer**：在它之前，RNN（循环神经网络）必须**按顺序**逐个处理单词，无法并行计算，且长距离依赖失效（前面的信息会被遗忘）。

**核心创新——自注意力机制**：让模型在处理每一个词时，都能同时扫描整句话，自动识别哪些词更重要，任意两个词的关联只需一步计算。

**三大关键组件**：

| 组件               | 作用                                                | 前端类比                             |
| ------------------ | --------------------------------------------------- | ------------------------------------ |
| **自注意力 + QKV** | 每个词发出查询(Q)，匹配其他词的键(K)，加权获取值(V) | `useEffect` 依赖匹配                 |
| **多头注意力**     | 多个注意力头从不同角度分析（语法、语义等）          | 代码多维度审查（性能、可读性、安全） |
| **位置编码**       | 给每个位置加顺序标记，弥补并行处理丢失的顺序信息    | React 列表渲染的 `key`               |

**编码器-解码器结构**：

- **编码器**：读取输入，理解其含义
- **解码器**：根据理解逐词生成输出
